## 발견 사항

### F-1 〔심각·수정완료〕 스냅샷이 전날 파일을 덮어쓰고 있었다
- **증상**: `data/trends_daily/`에 09-07, 09-08 두 파일뿐인데 수집은 3회 성공.
  09-08 파일 내용이 `videos:143` → `videos:141`로 바뀜 = **덮어쓰기**.
- **원인**: 러너는 UTC. 크론 `10 21 * * *`(=06:10 KST)은 UTC로 **전날 21:10**이라
  `datetime.date.today()`가 하루 전 날짜를 돌려준다. `daily-short.yml`만 `TZ=Asia/Seoul`을
  쓰고 있었고 나머지 3개 워크플로는 안 쓰고 있었다.
- **영향**: 일별 스냅샷이 하루씩 밀려 저장 → **어제 대비 증감(델타) 계산이 무의미**해진다.
  트렌드 점수 모델의 핵심 입력이 델타이므로 정확도에 직접 영향.
- **조치**: `trend-collect` / `channel-stats` / `briefing` 워크플로 job에 `env: TZ: Asia/Seoul` 추가.
- **잔여**: 이미 저장된 09-07·09-08 파일은 날짜가 밀려 있을 수 있다. 스냅샷이 2일치뿐이라
  버리고 새로 쌓는 편이 낫다. **다음 3일간 스냅샷 파일이 매일 1개씩 늘어나는지 확인 필요.**

### F-2 〔중요·미해결〕 제휴 링크 클러스터가 계속 0건
- 3회 수집 모두 `link_clusters: 0`. 영상 141~143편 중 설명란에 상품 링크가 있는 건 **6~7편뿐**.
- 클러스터 조건은 "서로 다른 채널 2곳 이상이 같은 상품에 링크". 링크 보유 영상이 7편이면
  같은 상품이 두 번 걸릴 확률이 거의 없다.
- **결과**: "정확히 어느 브랜드의 어떤 제품인가"를 링크로 역추적하는 설계가 **작동하지 않고 있다.**
  현재 브랜드 특정은 캐스토가 웹 검색으로 수동 조사한 12건에 의존한다.
- **후보 대응**(아직 판단 안 함): ①검색 쿼리를 '내돈내산·추천템' 계열로 넓혀 링크 보유 영상 비중을 올린다
  ②`min_channels`를 1로 낮추되 조회수 임계를 걸어 노이즈를 막는다 ③인스타 해시태그 통계를 보조 축으로 추가.

### F-3 〔최우선·사용자 대기〕 채널에 영상이 0편
- `data/channel_stats/2026-09-08.json` → `subscribers: 0, video_count: 0, total_views: 0`.
- 파이프라인은 매일 정상 생성되고 텔레그램으로 전송되지만 **업로드가 안 되고 있다**(수동 업로드 단계).
- 8주 컷오프(편당 1,000뷰·구독 100명) 판정 자체가 시작되지 않은 상태.
- **막고 있는 것**: ①로고·배너 미업로드 ②쿠팡 파트너스에 콕픽 채널 미등록(미등록 채널 홍보는 정지 사유)
  ③상품 캡처 0건(현재 영상에 실제 상품 사진이 없음).

### F-4 〔경미·수정완료〕 .DS_Store 3개가 git에 추적되고 있었다
- 매 작업마다 불필요한 변경으로 잡혀 `git pull --rebase`를 막았다(오늘 실제로 막힘).
- **조치**: `.gitignore` 생성(.DS_Store / out/ / __pycache__) + 추적 해제.

### F-5 〔경미·관측〕 daily-short 실행 시각이 크론과 어긋난다
- 크론은 23:09·00:37 UTC인데 최근 실행 기록은 05:05·01:07 UTC 등으로 불규칙하고,
  **09-09 예정 실행 2건이 목록에 없다**. 깃허브 크론 지연·유실은 알려진 현상이라
  백업 크론과 중복 가드는 이미 있다. 다만 **오늘은 두 크론 다 미발화**로 보인다.
- 지금은 영상 업로드가 안 되고 있어 영향이 없지만, 발행이 시작되면 결번이 생긴다. **관측 계속.**

### F-6 〔경미·수정완료〕 캡처 번호 중복 발급
- 같은 제품이 이름만 다르게 잡히면 새 번호가 발급된다(20=3번 얼음틀, 26=7번 무드등).
- 번호 재사용 금지 규칙 때문에 삭제하지 않고 **보류 처리**해 캡처 낭비만 막았다.
- 근본 해결은 이름 정규화 강화가 필요하나, 캡처가 시작되기 전까지는 영향이 작다.

## 정상 확인된 것

- **테스트 129개 전부 통과**, 15개 모듈 임포트 정상, 폐기한 `product_art`(AI 재현) 참조 없음.
- 워크플로 5종 최근 실행 전부 success — daily-short / trend-collect / briefing / channel-stats / weekly-trends.
- 유튜브 API 할당량: 제품별 재검색 제거 후 회당 400유닛(한도 10,000). 여유 충분.
- 상품 정확도 안전장치: 실사진 없으면 제품 이미지를 넣지 않고, 확인 안 된 브랜드명은 쓰지 않으며,
  남의 제휴 링크는 게시용으로 저장되지 않는다(전부 테스트로 고정).

## 스크립토(전체 점검)에 넘기는 확인 요청

1. **`TZ: Asia/Seoul` 누락은 픽토·스크립토 워크플로에도 있을 가능성이 높다.** 같은 UTC 함정이므로
   전 앱 워크플로에서 `date.today()` 계열을 쓰는 스텝에 TZ가 걸려 있는지 확인 권장.
2. **깃허브 크론 미발화**(F-5)가 다른 앱에서도 관측되는지 대조 필요.
3. `.gitignore` 부재로 인한 .DS_Store 추적이 다른 레포에도 있는지 확인 권장.
