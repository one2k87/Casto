# 캐스토 앱(대시보드) 구조·UX 점검과 개선 제안 (2026-09-09)

대상: `dashboard/index.html`(8.7KB, 단일 파일) + `manifest.json`
방법: 코드 전수 읽기 + 3앱 매니페스트 대조. **실제로 확인한 것만** 적는다.

---

## 0. 먼저 — 앱 문제의 유력 원인을 찾았다

### ⛔ P0. PWA scope가 3앱 모두 루트로 동일하고 `id`가 없다

| 앱 | scope | start_url | id |
|---|---|---|---|
| Scripto | `https://one2k87.github.io/` | `./index.html` | 없음 |
| Picto | `https://one2k87.github.io/` | `./index.html` | 없음 |
| **Casto** | `https://one2k87.github.io/` | `./` | 없음 |

`id`가 없으면 브라우저는 **start_url + scope로 앱 정체성을 판단**한다. 세 앱이 같은 scope를
선언하고 있으므로 홈 화면 설치·업데이트·실행에서 서로를 같은 앱으로 오인할 수 있다.
증상은 "설치했는데 다른 앱이 열린다 / 아이콘이 바뀐다 / 새로고침해도 옛날 화면"으로 나타난다.

**조치안**
```json
"id": "/Casto/dashboard/",
"scope": "https://one2k87.github.io/Casto/dashboard/",
"start_url": "./index.html"
```
scope는 자기 폴더로 좁히고 `id`를 명시한다. **3앱 공통 문제이므로 전 앱 점검 대상**이다.

## 1. 목적에 맞는 구조인가 — ❌ 목적이 바뀌었는데 화면이 안 따라갔다

09-08에 캐스토의 정체성이 **"픽담 유입 라인" → "개인 채널(콕픽) 커머스 전담"**으로 바뀌었다.
그런데 화면은 옛 목적 그대로다.

| 위치 | 현재 문구 | 문제 |
|---|---|---|
| 헤더 부제 | "픽담 쇼츠 배포 라인 · 콕픽" | 캐스토는 픽담 배포 라인이 아니다 |
| 바로가기 | "픽담 **(CTA 수렴처)**" | CTA 1순위는 쿠팡으로 바뀌었다 |
| 규격 요약 | "**CTA는 픽담으로**" | 같은 이유로 틀린 안내 |

**더 큰 구조 문제 — 지금 매일 해야 하는 일이 화면에 하나도 없다.**
현재 사용자의 실제 작업은 ①상품 캡처 넣기 ②영상 업로드 ③성과 확인 이 셋인데,
대시보드는 "오늘 쇼츠 만들어졌나"만 보여준다. 특히 **캡처 번호표는 로컬 HTML 파일**이라
앱 밖에 있다. 매일 반복하는 유일한 손작업이 앱에 없는 것이 가장 큰 설계 오류다.

## 2. 합칠 수 있는 것 — 카드 4개 → 3개, 콘텐츠는 절반으로

| 현재 카드 | 판정 |
|---|---|
| 오늘의 쇼츠 | 유지(최상단) — 단 "다음 할 일"과 합친다 |
| 이번 주 트렌드 | 유지하되 **접기**. 매일 볼 정보가 아니다 |
| 바로가기 4줄 | **2줄로**. 워크플로 실행기록 2개는 문제 있을 때만 필요 → 상태 점이 빨강일 때만 노출 |
| 콕픽 규격 요약 | **삭제**. 규격은 코드가 강제하므로 사람이 볼 이유가 없다. 문서로 충분 |

## 3~4. UI/UX·간편성 — 터치 타깃과 아이콘이 문제

- **앱 전환 버튼이 26×30px** (권장 44×44). 앱 사이를 오가는 주 동선인데 가장 누르기 어렵다.
- **`.row` 높이 ~31px** — 역시 44px 미달. 링크 4개가 다닥다닥 붙어 오조작이 난다.
- **아이콘이 사실상 없다.** 상태를 색점(dot)으로만 표시해 ①색각 이상 사용자에게 정보가 없고
  ②"녹색=무슨 뜻"인지 학습이 필요하다. 이모지 아이콘 + 한 단어면 설명이 필요 없어진다.
- **앱 이름이 `title` 속성에만 있다.** 모바일엔 hover가 없어 S/P/C/M 글자만 보인다.
- **다크 모드 변수는 다 정의돼 있는데 `data-theme="light"`로 고정**되어 죽은 코드다.
  `prefers-color-scheme` 한 줄이면 살아난다.
- **서비스워커가 없다.** manifest만 있어 설치는 되지만 오프라인이면 빈 화면이다.
- **새로고침 수단이 없다.** 실패하면 "상태 확인 불가"로 끝이고 재시도 버튼이 없다.

## 5. 코드 최적화·디버깅 — 발견 3건

- **죽은 코드**: `<span id="buildTag">`가 있는데 **채우는 코드가 없다**(항상 빈칸).
  버전 표기가 목적이었다면 `versions.md`의 v1을 넣어야 한다.
- **부분 실패 시 상태가 섞인다**: `last_short` fetch가 실패하면 `todayPill`/`todayBig`만 바뀌고
  `todaySub`("매일 08:09 자동 제작")와 `ciDot`는 옛 값이 남아 **성공한 것처럼 보인다.**
- **중복**: `<script>` 블록 2개, 동일한 fetch+try/catch 2벌 → 헬퍼 하나로 줄일 수 있다(약 20줄 감소).
- `manifest.json`의 `start_url`만 `./`이고 다른 앱은 `./index.html` — 통일 필요.

## 6. 순서대로 이용 — "오늘 뭐 하지?"에 답하는 화면이 아니다

사용자가 어제 실제로 한 말: **"다음날이라서 내가 어디까지 했는지 기억이 안 나."**
이건 UX 요구사항 그 자체다. 앱을 열었을 때 **오늘 할 일 딱 하나**가 보여야 한다.

**제안 구조 — 위에서 아래로 읽으면 그게 순서**

```
① 다음 할 일          ← 조건 분기로 자동 결정. 항상 1개만.
   "📸 캡처 17건 대기"  → [번호표 열기]
   (캡처가 채워지면) "🎬 영상 1편 업로드 대기" → [유튜브 스튜디오]
   (다 되면) "✅ 오늘 할 일 없음"

② 오늘 상태 (3칸 한 줄)
   🎬 쇼츠 완료 / 📦 캡처 17 / 👥 구독 0

③ 바로가기 2줄 (문제 있을 때만 3~4줄)
```

설명 문장을 없애고 **아이콘 + 숫자 + 버튼 하나**로 대체한다.
"매일 08:09 KST 자동 제작 → 텔레그램 전송" 같은 문장은 매일 읽을 정보가 아니다.

## 7. 사용자 편의 기능 — 우선순위 순 제안

| 순위 | 기능 | 근거 |
|---|---|---|
| **1** | **캡처 번호표를 앱 안으로** (`data/shot_queue.json`을 읽어 렌더) | 매일 반복하는 유일한 손작업. 지금은 로컬 파일이라 폰에서 못 본다. 앱에 들어오면 **폰으로 캡처 → 바로 확인**이 된다 |
| **2** | **다음 할 일 1줄** (조건 분기) | "어디까지 했는지" 기억할 필요를 없앤다 |
| **3** | **채널 성과 3칸** (`data/channel_stats/`) | 이미 매일 수집 중인데 화면에 없다. 8주 컷오프 판정의 근거 |
| **4** | 새로고침 버튼 + 실패 시 재시도 | 현재 실패하면 방법이 없다 |
| **5** | 서비스워커(최근 데이터 캐시) | 지하철·오프라인에서도 번호표를 볼 수 있다 |
| **6** | 다크 모드 자동 전환 | 변수는 이미 다 있다. 한 줄이면 된다 |
| 7 | 글감 요청서 링크 (`topic_requests.md`) | 픽토에 넘기는 목록 확인용. 자주 보진 않음 |

## 실행 순서 제안

1. **P0 매니페스트 수정**(id·scope) — 앱 문제의 유력 원인. 3앱 공통
2. 옛 목적 문구 3곳 교체 (픽담 CTA → 쿠팡 CTA)
3. 화면 재구성 (다음 할 일 / 상태 3칸 / 바로가기 2줄), 규격 요약 카드 삭제
4. 캡처 번호표 앱 내장 + 채널 성과 3칸
5. 터치 타깃 44px, 아이콘화, 다크 모드, 새로고침
6. 코드 정리(죽은 buildTag, 부분 실패 처리, 스크립트 통합) + 서비스워커

1~3은 반나절이면 끝나고 체감이 가장 크다. 4는 폰 작업 흐름을 바꾼다.
