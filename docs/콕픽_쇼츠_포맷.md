## 1. 메인 포맷: 「콕 열리는 상자」 (15초, 데일리 앵커)

**한 줄 규칙: 상자는 콕 3번을 통과해야만 열린다.**

| 초 | 화면 | 소스 |
|---|---|---|
| 0–0.5 | 콕이 클로즈업, 겉면에 오늘 제품 스탬프+제품명 자막 "오늘의 콕: 음식물처리기" (즉답, 낚시 아님) | 클립뱅크 A |
| 0.5–3 | 손가락 등장, 콕이 긴장→기대 표정. 자막 "콕 3번 통과하면 열립니다" | 클립뱅크 B |
| 3–11 | **콕! ×3** — 콕마다 근거 1줄(①월 전기료 ②크기·설치 ③실사용 조건). 콕 사운드=우드블록(사운드 브랜딩). 상자가 콕마다 말랑하게 눌림 | 클립뱅크 C + 자막 카드 |
| 11–15 | 통과 → 팟! 개봉, 제품 미니어처 뿅+종이 꽃가루, 도장 "오늘의 콕 ✅" / 미통과 → 도리도리 "다음콕 📦" | 클립뱅크 D/E |
| 고정 | 설명란·고정댓글: 픽담 글 링크 + 대가성 문구 | 자동 |

### 냉정 검증 — 4기준
1. **존재하지 않는 폼**: 언박싱(사람 손·실물)·리뷰·판정쇼는 넘치지만, "조건을 통과해야만 열리는 캐릭터 상자" 게임 구조는 유튜브에 없음. 주간 트렌드 스캔이 유사 포맷 출현을 감시(출현 시 차별점 강화).
2. **완주**: '열리나 안 열리나'는 시청자가 끝을 봐야 해소되는 미결 구조(언박싱 심리의 캐릭터화). 제품명은 0.5초에 공개하므로 낚시 혐오와 충돌 없음 — 유보되는 건 '판정'뿐. 15초·3비트 리듬·마지막 2초 보상.
3. **시리즈**: 완전 템플릿 — 매일 바뀌는 건 스탬프·근거 3줄·판정뿐, 콕이는 불변 → 캐릭터 자산 축적. 내장 스핀오프: **재심콕**(다음콕 제품이 가격 인하 시 재등장 — 연속 서사), **계절콕**(장마 전 제습기), **만원콕**(가격대 시리즈).
4. **쿠팡 수익**: 콕 3개 = 구매 결정 근거 그 자체(픽담 글의 조건분기 섹션 재활용). "오늘의 콕"=구매 허가 신호라 전환 의도가 가장 높은 순간에 CTA("자세한 비교는 픽담, 설명란👇"). 다음콕도 "이런 분은 조건콕"으로 전환 여지 유지.

## 2. 힉스필드 퀄리티 설계 — 클립뱅크 방식 (크레딧 절약 핵심)

매일 생성하지 않는다. **재사용 클립 은행**을 만들고 조립만 매일 한다.

| 뱅크 | 내용 | 제작 |
|---|---|---|
| A. 등장 | 콕이 대기·두리번(2–3초, 표정 3벌) | 로고 이미지 → 힉스필드 image-to-video |
| B. 긴장 | 손가락 다가옴, 콕이 움찔(2초, 2벌) | 〃 |
| C. 콕 반응 | 콕 찍혀 말랑 눌림(1초, 3벌 — 3콕에 다르게) | 〃 |
| D. 개봉 팝 | 뚜껑 팟+꽃가루(2–3초, 2벌) | 〃 |
| E. 다음콕 | 도리도리+미소(2초) | 〃 |
- 초기 구축: 클립 12~15개 ≈ 힉스필드 크레딧 300~450 (1회성). 이후 **주 2~3클립만 신규**(신선도) ≈ 주 60~90크레딧 → Plus 월 1,200 내 여유.
- 제품 컷: 쿠팡 파트너스 제공 소재 → 나노바나나(Unlimited·크레딧 0)로 미니어처/스탬프화 → ffmpeg 합성. 실패·소진 시 현행 카드 스타일 자동 폴백(발행 중단 없음).
- 캐릭터 일관성: 로고 원본 이미지를 항상 참조 이미지로 사용(같은 콕이 유지).

## 3. 서브 포맷 (주 1~2회 로테이션, 동일 파이프라인)
- **「콕이 vs 콕이」**: 상자 2개 나란히 — 조건 자막("4인 가구")에 맞는 쪽만 열림. A vs B 비교 검색 수요 직격, 클립뱅크 그대로 2벌 배치.
- **「몇콕이면 살까?」**: "3만원이면 콕? 5만원이면 콕?" 가격 한계선 판정 — 댓글 참여("얼마면 콕?") 유도, 특가 알림과 결합 시 전환 최강.

## 4. 인스타 변형 (20초)
동일 소재 → 개봉 후 마지막 3초를 **'오늘의 콕 카드'**(파스텔 정물 1장: 제품+가격+한 줄)로 마무리 → 저장 유도. 캡션 "프로필 링크 → 오늘의 콕 자세히".

## 상품 노출 규칙 (2026-09-08 추가)

> "채널을 보는 사람에게 어떤 상품인지 모양 제대로 보여야 하고 정보를 제대로 전달해야 해."

시청자가 구독하는 이유는 **재인**이다 — 피드에서 스치듯 본 물건을 우리 영상에서 다시 알아보는 것.
그러려면 화면에 **그 물건의 실제 모양**이 있어야 한다. 클레이 콕이는 채널의 얼굴이지 상품 설명이 아니다.

### 3단계 (catalog.render_mode)

| 단계 | 조건 | 화면 | 자막 이름 |
|---|---|---|---|
| `exact` | **실제 사진** 보유(캡처·픽담·파트너스·제조사) | 상품 사진이 주인공, 콕이는 좌하단 조연 | 브랜드 + 모델 |
| `named` | 이름만 확정, 사진 없음 | 클레이 아트 (제품 이미지 없음) | 브랜드 + 모델 |
| `generic` | 아무것도 없음 | 클레이 아트 | 카테고리명("코팅팬") |

**틀린 사진·틀린 브랜드명은 사진이 없는 것보다 나쁘다.** 그래서 `find()`가 후보를 하나로 좁히지 못하면
찾지 못한 것으로 처리하고, LLM에게는 브랜드명을 지어내지 못하게 막는다(`build_script`의 `[확정된 상품]` 블록).

### 왜 실사진 자동 수집이 불가능한가 (2026-09-08 실측)

| 경로 | 결과 |
|---|---|
| 쿠팡 상품 페이지 스크래핑 | **403** — 데이터센터 IP 차단. 깃허브 액션에서 불가 |
| 쿠팡 오픈 API | 파트너스 수익 조건 미달로 발급 불가 |
| 네이버 쇼핑 검색 API | 2026-07-31 종료 |
| 픽담 글 이미지 | 현재 쿠팡 링크·상품 이미지가 없다(wp-json 실측) → 6-C가 풀리면 해결 |
| 남의 유튜브 썸네일·릴스 캡처 | 저작권 위반. 선택지가 아니다 |

→ **제품을 AI로 재현하는 선택지는 폐기했다(2026-09-08).**
> "절대로 제품을 가상으로 재현하면 안 돼. 그 즉시 시청자는 바로 돌아설 거야."

커머스 채널의 자산은 신뢰 하나뿐이고, 시청자는 실물과 다른 그림을 즉시 알아본다.
**사진이 없으면 제품 이미지를 아예 넣지 않는다** — 없는 게 가짜보다 낫다.
사람은 캡처를 폴더에 넣는 것까지만 하고, 이름 정리·등록·누끼·배치·자막 반영은 코드가 한다.

### 사진이 들어오는 경로

1. **자동** — 픽담 글의 `<!--KOKPICK ... -->` 블록(`brand`/`model`/`image_url`/`coupang_url`).
   픽담이 자기 파트너스 계정으로 확정한 값이라 사람이 손댈 일이 없다. **현재 최우선 블로커**(브리프 6-C).
2. **캡처 반입(현재 주력)** — **번호로만 주고받는다.**
   `assets/products/캡처_넣는곳/_목록.md`에 상품마다 고정 번호가 적혀 있고, 사람은 `3.png`로 저장만 한다.
   `capture_import.py`가 번호 → 제품 매칭, 카탈로그 등록, 파일 이동을 하고, 워크플로가 매일 자동 실행한다.
   **번호는 한 번 붙으면 바뀌지 않고 완료된 번호는 재사용하지 않는다** —
   어제 3번을 보고 캡처해 둔 것이 오늘 다른 제품의 3번이 되면 엉뚱한 사진이 붙기 때문이다.
   영상 생성 시 사진이 없으면 텔레그램으로 "N번 저장해주세요"가 온다.
3. **필요 목록 확인** — `python catalog.py` → `out/이미지_요청서.md`에 필요한 상품 목록이 뜬다.
   쿠팡 파트너스 링크 생성 화면에서 이미지 저장 + 내 링크 복사 → `assets/products/` + `data/catalog.json` 등록.

### 하지 않는 것

- 다른 크리에이터의 썸네일·릴스 캡처 사용 (저작권)
- 남의 파트너스 링크를 게시용으로 재사용 (수수료 탈취 + 정책 위반) — `catalog.put`이 강제로 버린다
- 확인 안 된 브랜드명 추정 표기 (오정보)
