# 유튜브 소유자 토큰 발급 런북 (1회, 약 10분) — 2026-10-19 최신 콘솔 메뉴명으로 갱신

왜: Make의 유튜브 업로드가 간헐적으로 403을 내며 제목 `unknown` 공개 영상을 남긴다(10/13·10/15 네 편).
Make 커뮤니티에 2025-10부터 같은 보고가 있고 원인 미상 — Make 쪽 수정을 기다릴 수 없다.
해법: **업로드는 Make가 하고, 뒤처리는 우리가** 한다. 채널 소유자 토큰이 있으면 publish.py가 좀비를 찾아
오늘 편의 제목·설명·태그를 붙여 정상 발행으로 되살리고(403이 나도 발행은 된다), 중복은 비공개로 돌린다.
같은 토큰으로 YouTube Analytics API도 열린다(정체성 실험 자동 측정 — 사람 손 하나 더 줄어든다).

famto는 키·토큰을 만지지 않는다. 아래는 사용자가 하는 클릭 경로. 메뉴 이름은 2026-10 구글 문서 기준
(콘솔은 "OAuth 동의 화면"이 **Google 인증 플랫폼**으로 바뀌었다 — 브랜딩 / 잠재고객 / 클라이언트 / 데이터 액세스 네 탭).

## 0. 어느 구글 계정으로 하나

콘솔 작업(1~3단계)은 **아무 구글 계정**이나 된다(AI Studio 키를 만든 계정이 편하다 — 프로젝트가 이미 있으니).
4단계 승인 창에서만 **콕픽 채널을 가진 계정**(Make 연결과 같은 계정, 브랜드 계정 '픽핸드/콕픽')으로 로그인한다.

## 1. 프로젝트 고르고 API 두 개 켜기 (3분)

1. https://console.cloud.google.com 접속 → 상단 프로젝트 선택 상자 → **AI Studio 키(LLM_API_KEY)가 있는 프로젝트** 선택.
   (프로젝트 이름은 https://aistudio.google.com/api-keys 표의 Project 열에서 확인. 없으면 "새 프로젝트" 아무 이름이나.)
2. 왼쪽 햄버거 메뉴 ☰ → **API 및 서비스 → 라이브러리** → 검색창에 `YouTube Data API v3` → 클릭 → **사용**.
3. 같은 방법으로 `YouTube Analytics API` → **사용**.

## 2. Google 인증 플랫폼(동의 화면) 만들기 (3분)

1. ☰ → **Google 인증 플랫폼**(또는 "API 및 서비스 → OAuth 동의 화면" — 같은 곳으로 간다) → **브랜딩**.
2. 처음이면 "시작하기" 버튼 → 네 단계:
   - **앱 정보**: 앱 이름 `Casto`, 사용자 지원 이메일 = 본인 → 다음
   - **잠재고객(대상)**: **외부(External)** → 다음
   - **연락처 정보**: 본인 이메일 → 다음
   - **완료**: 정책 동의 체크 → 계속 → **만들기**
3. 왼쪽 **잠재고객** 탭 → 게시 상태가 **"테스트 중"**이면 **「앱 게시」** 버튼 → 확인 → **"프로덕션"**이 되면 끝.
   ⚠️ 이게 제일 중요하다. "테스트" 상태의 외부 앱은 **refresh token이 7일 뒤에 죽는다**(구글 OAuth 정책). 프로덕션이어야 영구.
   "확인(인증)이 필요합니다" 같은 안내가 떠도 **무시**해도 된다 — 본인 한 사람만 쓰는 앱이라 인증 없이도 동작한다(경고 화면만 뜬다).
4. (선택) **데이터 액세스** 탭은 손대지 않아도 된다 — 범위는 스크립트가 승인 때 직접 요청한다.

## 3. 클라이언트(데스크톱 앱) 만들기 (2분)

1. Google 인증 플랫폼 → **클라이언트** 탭 → **「+ 클라이언트 만들기」**.
2. 애플리케이션 유형 **데스크톱 앱**, 이름 `casto-desktop` → **만들기**.
3. 만들어진 창에서 **JSON 다운로드**(또는 목록의 ⬇ 아이콘) → 파일을 `~/Downloads/client_secret.json` 이름으로 둔다.
   (리디렉션 URI는 등록할 필요 없다 — 데스크톱 앱은 `http://127.0.0.1:포트` 루프백을 그냥 허용한다.)

## 4. 토큰 발급 (2분, 터미널)

```
cd ~/Desktop/SolvUp_Workspace/Casto
git pull
python3 yt_auth.py ~/Downloads/client_secret.json
```
- 브라우저가 열린다 → **콕픽 채널이 있는 계정**으로 로그인. "계정 선택" 화면에서 **브랜드 계정(콕픽 / 픽핸드)** 이 따로 보이면
  반드시 그걸 고른다(일반 계정을 고르면 채널이 아니라 개인 계정 토큰이 나온다).
- "Google에서 확인하지 않은 앱" 화면이 뜨면 → **고급** → **Casto(안전하지 않음)(으)로 이동** → 권한 항목 체크 → **계속**.
- 브라우저에 "승인 완료"가 뜨고, 터미널에 세 줄이 찍힌다:
  `YT_CLIENT_ID = …` / `YT_CLIENT_SECRET = …` / `YT_REFRESH_TOKEN = …`
- `refresh_token이 없습니다` 라고 나오면: https://myaccount.google.com/permissions 에서 Casto 접근 권한을 삭제하고 다시 실행.

## 5. GitHub Secrets 등록 (2분)

https://github.com/one2k87/Casto/settings/secrets/actions → **New repository secret** 를 세 번:
`YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN` — 이름은 정확히, 값은 터미널에 찍힌 그대로(공백 없이).

끝. famto에게 "유튜브 토큰 넣었어" 한 줄. 그러면:
- `data/publish_hold.txt` 보류가 **자동 해제**된다(토큰이 있으면 publish.py가 보류를 무시한다 — 파일은 famto가 지운다).
- 다음 발행일부터 Make가 403을 내도 좀비가 자동으로 오늘 편이 된다. 텔레그램엔 평소처럼 링크가 온다.

## 6. 하지 않아도 되는 것 / 하지 말 것

- Google의 **YouTube API 감사(audit) 신청**·앱 인증(verification) — 본인 1인 사용이라 불필요. Make를 완전히 뺄 때 다시 본다.
- `client_secret.json` 을 저장소에 넣는 일 — **절대 금지**. 토큰 발급 뒤 파일은 지워도 된다.
- 테스트 사용자 추가 — 프로덕션으로 게시하면 필요 없다.
